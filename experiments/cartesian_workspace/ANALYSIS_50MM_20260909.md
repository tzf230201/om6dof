# OM6DOF experiment analysis — 50 mm grid, September 9, 2026

## Experiments actually performed

Four offline C++17/Eigen/KDL scans used **the same URDF model**, each evaluating
3,911 points within a conservative sphere of radius 491.309 mm centered on
`world`, with tip `end_effector_link`. The grid spacing is 50 mm in X/Y/Z. Each
run produces 19 constant-X, 19 constant-Y, and 19 constant-Z planes:
-450, -400, ..., 0, ..., +450 mm. Points outside the sphere were not tested.
White areas on the maps are not failed results.

No commands were sent to the robot. This is an endpoint geometry/kinematics
study, not a measurement of physical accuracy, mechanical strength, or motion
safety.

| Run | Gripper orientation | Seed bank / nearest seeds / iterations | Joint margin | Positions found | Poses found | Scan time |
|---|---|---|---:|---:|---:|---:|
| [Standard radial](results/cpp_50mm_20260909_radial/index.html) | Horizontal, pointing outward | 2,000 / 4 / 100 | 0.02 rad | 1,928 | 380 | 3.68 s |
| [Fixed orientation](results/cpp_50mm_20260909_fixed/index.html) | RPY = 0/0/0, pointing +X | 2,000 / 4 / 100 | 0.02 rad | 1,928 | 154 | 3.99 s |
| [Larger radial search](results/cpp_50mm_20260909_radial_deep/index.html) | Horizontal, pointing outward | 10,000 / 12 / 200 | 0.02 rad | 1,930 | 380 | 9.07 s |
| [Radial with URDF hard limits](results/cpp_50mm_20260909_hard_limits/index.html) | Horizontal, pointing outward | 2,000 / 4 / 100 | 0 rad | 1,932 | 388 | 3.70 s |

READY and zero are added to the nearest seeds; pose IK also receives up to two
position-IK result seeds. Every candidate must pass FK position error <=1 mm
and, for a pose, orientation error <=0.5 degrees. Endpoints are checked with
25 mm-radius capsules. Times are wall-clock scan times including the FK bank
and CSV writing, not compilation, xacro, or report generation. Each time is one
measurement per configuration, not a repeated benchmark. Do not compare
directly with the earlier 60 mm Python run: point counts, RNG, and solver step
rules differ.

## Main findings

### 1. Gripper orientation restricts results much more than XYZ alone

The standard radial search found solutions for **1,928 positions**, but only
**380** had the requested horizontal radial orientation. With fixed global
orientation RPY0/0/0, the number of poses found fell to **154**, while the number
of unconstrained positions found was unchanged.

An unconstrained-position map therefore cannot answer whether the robot can
grasp an object with a particular gripper direction. These are results for two
orientation policies, not proof that other orientations are impossible and not
a scan of all SO(3).

### 2. Z=200 and 250 mm have the most radial-orientation poses

Excerpt from the [Z-plane statistics](results/cpp_50mm_20260909_radial/slices.csv):

| Constant Z | Points on plane | Unconstrained positions found | Radial poses found |
|---:|---:|---:|---:|
| 0 mm | 293 | 177 | 34 |
| 50 mm | 293 | 186 | 46 |
| 100 mm | 293 | 189 | 47 |
| 150 mm | 277 | 188 | 53 |
| 200 mm | 249 | 181 | 68 |
| 250 mm | 221 | 162 | 68 |
| 300 mm | 185 | 141 | 42 |
| 350 mm | 145 | 110 | 0 |
| 400 mm | 101 | 76 | 0 |
| 450 mm | 45 | 35 | 0 |

At Z=350–450 mm, several positions were still found, but not with the gripper
horizontal and radial. Blue here therefore does not mean "the arm cannot
reach." Z=200–250 mm is a candidate working-height range for tasks using this
tested orientation, **not a guarantee that every XY point at those heights is
reachable**. Plane sample counts vary because the domain is a sphere; consider
the number of tested points when comparing success counts.

### 3. The rear differs from the front

On the negative-X side, the standard radial search still found many
unconstrained positions but no requested radial poses. The URDF snapshot gives
joint1 a range of -90 to +90 degrees, joint4 -72 to +72 degrees, and joint6
-90 to +90 degrees; the operational margin narrows those ranges further.

**Interpretation, not proof of a single cause:** this pattern is consistent
with limited base and wrist rotation. Do not identify a specific joint as the
definitive cause without changing one model limit at a time and checking
collision meshes. These runs did not change any physical robot limits.

### 4. The small operational margin is not the main explanation for unresolved regions

Removing the 0.02 rad margin (~1.146 degrees) in simulation increased positions
found from 1,928 to 1,932 and poses from 380 to 388. This difference is much
smaller than the gap between unconstrained positions and oriented poses.
Changing the limits also changes the sampled seeds; this is a limited result
comparison, not exhaustive proof of the margin's effect. Removing the physical
robot's margin on this evidence alone is not recommended.

### 5. A larger search helps, but only slightly on this grid

A 5× larger seed bank, 3× as many nearest seeds, and 2× as many iterations added
two positions, while radial poses remained at 380. Aggregate results were
relatively stable across the tested search budgets; this is **not mathematical
proof that every red point is impossible**. The new bank does not contain
exactly all the old bank's seeds, and matching aggregate counts do not guarantee
identical joint candidates or point identities.

The number of points whose best pose candidate was near-singular fell from 12
to 10. This illustrates why singularity cannot be assigned absolutely to XYZ:
the selected joint configuration also matters.

## Reading the colors and understanding the limitations

- Green: a pose solution is within tolerance and rcond is at least 0.01.
- Yellow: a pose solution exists, but the best candidate found has rcond<0.01
  (the Jacobian's linear rows are normalized by a 0.3 m length).
- Blue: a position solution exists, but a pose with the tested orientation was
  not found.
- Purple: only position candidates colliding under the capsule model were found.
- Red: no position solution was found within the search budget.

The model does not include a table/floor, environmental obstacles, payload,
calibration, backlash, compliance, motor capabilities, or paths to targets.
Points in the negative-Z hemisphere remain part of the domain. The success
percentage is not a continuous-volume percentage or the probability of success
on a physical robot.

For stronger evidence of a suspected mechanical dead zone, scan locally at
finer resolution, test multiple gripper orientations and more seeds, and check
collision meshes before considering design changes. This report does not
authorize automatic robot trajectories.

The regenerated `index.html` links to `viewer3d.html`. The self-contained viewer
lets you rotate/pan/zoom the point cloud, filter categories and constant-X/Y/Z
planes, and inspect individual points. It uses a JavaScript Canvas projection
with embedded scan data; no WebGL, CDN, or external network access is required.
It displays the existing C++ results and does not run IK or robot commands.
Filtering or rotating the view does not change any finding reported above.

If a Flatpak browser cannot open the local file, use the localhost HTTP serving
instructions in the [README](README.md#interactive-3d-viewer). For an existing
server serving `/tmp/om6dof-uji-50mm` on port 8765, refresh
`http://127.0.0.1:8765/viewer3d.html` after regenerating the report.

The `results/` folder contains local artifacts and is ignored by Git. The
documentation and programs remain separate from the controller/teleop runtime.
Use `run_cpp.sh` with a new output directory to repeat the scan, or follow the
README's report-only regeneration commands to update the presentation without
recalculating the existing experiment.
