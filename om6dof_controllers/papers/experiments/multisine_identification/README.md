# OM6DOF multisine identification experiment

This directory keeps the physical multisine identification artifacts used by
the manuscript in one place.

- `data/`: raw CSV recordings and gravity/friction fit YAML files.
- `visualizations/`: interactive HTML visualization derived from the recorded
  signals.

The CSV `effort_raw` fields contain DYNAMIXEL Present Current register values;
they are not calibrated joint torque measurements. The paper's reproducible
figures and held-out summaries are generated by
`../../scripts/generate_multisine_results.py`.

These files were moved here from `/home/kublab/tf_identification` and
`/home/kublab/visualizations` on 2026-08-29. No source data were deleted or
compressed.

## Current evidence and limitations

The present data establish a repeatable current-domain baseline, not a complete
physical robot identification:

- The `teaching_all` run contains 18,156 samples over 181.053 s at about
  100.27 Hz for all six arm joints.
- Position, reported velocity, and raw Present Current were recorded while the
  trajectory/position loop was active.
- The existing gravity coefficient is expressed as raw current per
  **nominal-model** N m. It is not yet an independently calibrated actuator
  torque constant.
- Joint velocity is quantized, and the friction model has not yet been
  validated with controlled constant-speed forward/reverse trials.
- Current-only quasi-static data cannot, in general, uniquely separate motor
  torque scale from physical link mass and center-of-mass parameters.

Consequently, the current paper result must be described as a preliminary
current-domain OM6DOF instantiation. Physical mass, CoM, calibrated torque, and
autonomous commissioning remain experimental objectives.

## Research direction

The target system is an autonomous, observability-aware self-commissioning
pipeline for low-speed direct teaching. Given trusted URDF kinematics,
collision geometry, joint limits, actuator feedback, and an environment model,
the robot should:

1. qualify actuator channels and verify current polarity;
2. construct a collision- and limit-aware calibration space;
3. determine which gravity-parameter combinations are observable;
4. select bounded informative experiments;
5. identify gravity and friction without conflating them unnecessarily;
6. validate on independent trials; and
7. enable pure-current compensation only on axes that pass all gates.

Each candidate calibration motion is treated as an **epistemic action**: a
safety-constrained physical action chosen because it is expected to reduce
uncertainty in the robot's own compensation model. This provides the conceptual
link between the safe set, observability analysis, information gain, and the
validation gate.

After observability analysis, the workflow branches explicitly:

```text
                       Is torque scale independently known?
                              /                  \
                            no                    yes
                            |                      |
                  per-joint current-domain   physical base-parameter
                         identification          identification
                            |                      |
                            +---- validation -----+
```

The current-domain branch produces useful actuator commands but cannot treat
per-joint coefficients as transferable physical link parameters. Descendant-
subtree subtraction and shared base-parameter reasoning are permitted only in
the physically calibrated branch.

The framework must not force an estimate of every individual link mass and
CoM. For a serial manipulator, only a set of base/minimal gravity-parameter
combinations may be observable. Distal-to-proximal experiments can aid
diagnosis and initialization, but the schedule must be selected by
observability and followed by a global refinement; distal-first ordering alone
is not the claimed contribution.

## Experiment roadmap

### E1 -- Known-payload current-to-torque calibration (next priority)

**Purpose.** Break the otherwise unavoidable scale ambiguity between raw
DYNAMIXEL Present Current and physical gravity torque. This experiment must be
completed before reporting physical mass, CoM, or torque in N m.

**Required payload description.** Measure and record:

- payload mass using a scale;
- payload CoM relative to its attachment frame;
- attachment pose relative to the end-effector frame;
- mounting repeatability and uncertainty; and
- an identifying photograph or drawing of the assembly.

A known mass without a known attachment/CoM is insufficient. The payload mass
will be chosen only after an offline URDF calculation demonstrates that every
planned pose remains inside conservative joint-current and torque limits.

**Protocol.**

1. Keep the arm mechanically supported for mode changes and emergency stop
   preparation. Confirm joint limits, current limits, temperature, voltage,
   fault status, controller ownership, and an unobstructed workspace.
2. Select static or very slow poses that give large, differently signed
   payload gravity increments while preserving joint, self-collision, ground,
   and current margins. Do not use poses with external support contact.
3. Execute the same pose sequence without the payload and with the payload.
   At every pose, wait for settling and record joint position, reported
   velocity, raw Present Current, voltage, temperature, operating mode, and
   timestamps. No person may push or hold the arm during accepted samples.
4. Repeat the sequence in forward and reverse order and perform multiple
   mounting trials. This exposes drift, backlash, hysteresis, and temperature
   dependence.
5. From the known payload model, compute its gravity-torque increment
   `delta_tau_payload(q)`. Pair bare and loaded samples at matching poses and
   form `delta_current = current_loaded - current_bare`.
6. For each sufficiently excited joint, estimate the signed scale

       delta_current_i = a_i * delta_tau_payload_i + error_i,

   where `a_i` has units raw current per N m. The physical conversion is
   `tau_i = current_i / a_i` after polarity and offset handling.
7. Reject an axis when payload torque variation is too small, its regression
   is ill-conditioned, or uncertainty is excessive. A gravity payload cannot
   calibrate a vertical-yaw axis such as joint1 when its payload gravity torque
   is approximately zero; that axis requires a known external torque or a load
   cell.
8. Validate on separate poses and a separate load/unload trial that were not
   used for fitting. Report slope confidence intervals, RMSE, MAE, maximum
   error, residual-versus-pose plots, repeatability, and temperature range.

**Acceptance gate.** A joint receives a physical current-to-torque scale only
if polarity confidence, excitation span, conditioning, parameter uncertainty,
held-out error, repeatability, current margin, and thermal/fault checks pass.
Failure blocks unsupported free Mode 0 activation; zero current is considered
safe only while the arm is mechanically supported.

**Expected first axes.** Joint2, joint3, and joint5 are the initial candidates
because the existing trajectory produces meaningful gravity variation there.
Joint1, joint4, and joint6 must not be forced into a physical fit when the known
payload does not excite them sufficiently.

### E2 -- Symmetric bidirectional friction identification

At matched configurations, command several bounded constant speeds in both
directions. Trim acceleration and settling segments. Under an approximately
odd friction model,

    gravity + bias ~= (current(q, +v) + current(q, -v)) / 2
    friction       ~= (current(q, +v) - current(q, -v)) / 2

Use several speed magnitudes to separate Coulomb and viscous components. Check
direction asymmetry and Stribeck/start-up behavior instead of assuming the
simple model is valid. The existing multisine velocity trace is not the final
friction experiment.

### E3 -- Observability and safe experiment selection

Construct the URDF-derived gravity regressor, whiten and column-normalize it,
and use SVD/QR to retain only practically observable parameter combinations.
Candidate poses and trajectories must respect joint, velocity, acceleration,
current, duration, self-collision, ground, and environment constraints. Select
experiments by incremental information gain on the observable subspace rather
than by a fixed joint order.

### E4 -- Independent Mode 0 transfer validation

The current baseline was collected under the position loop, whereas direct
teaching deploys raw-current Mode 0. Test the calibrated model in Mode 0 with
the arm initially supported, conservative current saturation, slew-rate
limits, thermal monitoring, and a hardware emergency stop. Compare predicted
and measured holding current on independent poses before any free hand-guiding
trial.

### E5 -- Direct-teaching evaluation

After E1--E4 pass, compare at least:

- position/current-based Mode 5 behavior;
- uncompensated supported Mode 0 behavior; and
- validation-gated gravity and fractional friction compensation in Mode 0.

Measure required hand force or external torque, drift, settling, tracking of
the compensation command, current saturation, temperature, and user task
performance. Qualitative impressions alone are insufficient for the paper.

### E6 -- Payload-change and recommissioning study

Introduce a second known payload or attachment configuration. Evaluate whether
no-contact validation residuals detect model invalidation and whether the
framework can recalibrate only the affected parameter blocks. Residuals during
human teaching must not be interpreted directly as morphology change because
human-applied torque is itself a residual source.

## Reproducibility and data policy

Each new run must receive its own immutable directory containing:

- raw CSV or rosbag data;
- expanded URDF and controller configuration;
- payload description and uncertainty;
- command-line invocation and software commit;
- operating mode, current limits, supply voltage, and temperature;
- fit parameters, covariance/confidence intervals, and acceptance decision;
- held-out metrics and plots; and
- a checksum manifest.

Training and validation trials must be physically separate whenever possible,
not merely random rows from the same periodic run. Historical or
pre-URDF-correction logs must remain clearly marked and must not be mixed with
confirmatory results.
